# Task 3b report — defer the similar strip

## What shipped

`/photo/{id}` no longer computes `similar_photos(...)` (a full-library scan)
before returning HTML. It renders immediately with the image, EXIF, tags,
sources, and collection collage, plus a placeholder for the similar strip.
A new `GET /photo/{photo_id}/similar` route computes the strip and returns it
as an HTMX fragment that swaps into the placeholder on page load.

Note: `similarity` (the `similarity_breakdown` table shown when opened via
`ctx=similar:<id>`) is a cheap single-pair computation and stayed inline in
`/photo`, as instructed. The `_photo_context` resolution for `ctx=similar:*`
(used to build the collection a "similar" leaf pages within) also stays
inline in `/photo` — it's inherent to that navigation mode, not the deferred
strip, and out of scope per the task brief.

## Files changed

- `web/app.py`
  - Extracted `_collection_for_photo(ctx_param, params, photo_id)` — the
    "resolve collection, fall back to the library if the photo isn't a
    member" logic that used to live inline in `photo_detail`. Both
    `photo_detail` and the new `photo_similar` route call it, so the
    collection-member exclusion applied to the similar strip is guaranteed
    identical between the two.
  - `photo_detail` (`GET /photo/{photo_id}`): removed the inline
    `similar_photos(...)` call and its member-exclusion; no longer passes
    `similar` to the template.
  - Added `photo_similar` (`GET /photo/{photo_id}/similar`): owner-scoped
    (404 if the photo isn't the caller's, mirroring `/photo`), computes
    `similar_photos(...)`, resolves `collection_grid` via
    `_collection_for_photo`, applies the same member-exclusion, and renders
    `_similar.html`.
- `web/templates/_similar.html` (new) — the extracted "Similar photos"
  partial: same markup, same links (`ctx=similar:<id>`,
  `location.replace(...)`), same reasons, same empty-state copy. Its
  outermost element is `<div id="similar">…</div>`, matching the id of the
  placeholder it replaces via `hx-swap="outerHTML"`.
- `web/templates/photo.html` — replaced the inline "Similar photos" block
  with a placeholder:
  `<div id="similar" hx-get="/photo/{{ photo['id'] }}/similar{{ ('?' + ctx_query) if ctx_query else '' }}" hx-trigger="load" hx-swap="outerHTML">` containing
  the `<h3>` and a "Finding similar photos…" hint. `ctx_query` is carried
  forward so the fragment request resolves the identical collection.
- `docs/design.md` — §9.2 ("Planned, not yet shipped: two-phase similar" →
  "Shipped: `/photo` paints instantly, the similar strip loads async"), §13
  (`/photo/{id}` bullet notes the async load), §18 (future-work bullet marks
  this step done, keeps the finer KNN/refine two-phase split as the
  remaining follow-up).

## Deviations

None from the brief. `_photo_context`'s own `similar_photos` call (used to
resolve the `ctx=similar:*` collection for paging) was intentionally left
inline in both routes — it's a different call (over the *origin* photo, for
paging) from the deferred one (over the *current* photo, for the strip), and
the task explicitly scoped "similar" ctx handling as out of bounds.
